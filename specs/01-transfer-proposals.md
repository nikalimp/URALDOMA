## 2. Нововведения — запрос клиенту
Отправляем клиенту вопросы, на которые нет ответа в открытых данных. Не спрашиваем то, что уже видно на сайте.
1. Что на текущем сайте раздражает вас или клиентов?
2. Каких страниц или разделов не хватает? (новые услуги, кейсы, цены, команда, блог, филиалы)
3. Какие функции нужны? (онлайн-запись, калькулятор, оплата, личный кабинет, интеграция с CRM, мультиязычность)
4. Что изменилось в бизнесе с момента запуска сайта? (услуги, цены, адреса, команда, позиционирование)
5. Кто будет править сайт после переноса и насколько часто?
6. Дизайн: сохраняем узнаваемость, обновляем или делаем заново?
7. Есть ли дедлайн? (сезон, рекламная кампания, истечение хостинга или подписки на конструктор)

## 3. Наши предложения по улучшениям
Из анализа: каждая проблема из §8 аудита → предложение. Плюс то, что даёт перенос на наш стек.

| # | Предложение | Что даст (факт или ожидаемый эффект) | Трудозатраты | Приоритет |
|---|---|---|---|---|
| 1 | Перенос на Next.js + статическая сборка: весь текст в HTML, Lighthouse ≥ 90 | Нейросети и поисковики видят весь контент; быстрее загрузка | входит в перенос | Must |
| 2 | llms.txt, robots.txt для AI-ботов, Schema.org на всех страницах | Основа видимости в ChatGPT, Алисе AI, Perplexity | входит в перенос | Must |
| 3 | Прямые ответы в первом абзаце ключевых страниц, FAQ | Цитируемость в нейросетях и быстрых ответах Яндекса | | Should |
| 4 | Страница на каждую услугу / частый вопрос (по исследованию) | Новые запросы в поиске и нейросетях | | Should |
| 5 | Юридическое: политика ПДн, согласие в формах, cookies, реквизиты | Соответствие 152-ФЗ | входит в перенос | Must |
| | | | | |

Приоритеты: **Must** — без этого перенос не имеет смысла или нарушает стандарт; **Should** — сильно улучшает результат; **Could** — можно позже, на абонементе.
